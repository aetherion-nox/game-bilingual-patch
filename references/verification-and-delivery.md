# 验证、安装与交付

为开始实现、修复覆盖回退、打包、安装或报告完成的任务读取本文件。验证应适应当前引擎，不要求使用某个项目的工具链。

## 文本与格式验证

- 以复合键核对输入输出，发现一对多、重复键、版本冲突、缺失源文或译文时显式处理。
- 除获准的译文编辑和受控重排外，主语言语义内容完整；只增加空白的断行也要按语言规则检查。其他语言、可见性、字幕时序及非目标元数据保持预期值。
- 区分占位符的命名、位置、类型、格式修饰、转义及复数分支。某些格式化器不支持同一参数重复出现，不能只比较占位符集合就宣称安全。
- 对长玩家名／物品名、大数量、小数、负数等实际可出现的值验证替换和布局；缺少格式化器证据时记录为未支持，而非盲目开启动态双语。
- 富文本标记符合已确认的语法：需要闭合的标签正确配对，合法独立图标标记不因没有结束标签而被误判。控制码、输入设备图标、组合键、可交互文本语义不被清理正则破坏。不能仅依赖“去掉标签后的字符串”验证渲染。
- 匹配与生成应可复现。为真实误判、共享ID、长句回退、空译文和重复图标等已出现问题保留有意义的回归用例；扩展覆盖时比对已有有效输出，不能无说明地降低原覆盖。
- 单独核验主辅语言块完整性、语序、对象／数值对应及语言切换边界；主文仍是输出子序列、占位符数量一致、没有异国语言字符，都不足以证明没有语句穿插。对运行时拼接模板检查组合结果。辅助语言允许专名、玩家输入或有意引用，不以字符集一刀切误删。
- 示例反馈触发规则级复查：定位共同生成路径，测试同类其他资源与原本正确的反例，再读回最终补丁；逐ID记录不能安全处理的情况。不要把示例修好或自动检查通过表述成整类画面已目视通过。

## 最终产物与运行验证

1. **最终文件读回：** 重新打开实际要发布的加密／压缩／编译补丁，核对内容、记录数量和元数据，不只检查中间JSON或文本。针对UI修改列出允许的资源与字段；可行时从原资源重构预期后比较，发现额外改动。
2. **加载验证：** 确认支持的游戏版本、补丁优先级、加载或挂接日志。验证游戏可启动并进入代表场景；成功挂载不表示每一条文字都被实际使用。
3. **画面与交互验证：** 按消费者类别抽查，不必穷举全部文字。覆盖最长代表句、多条提示同时出现、长按／组合键、字幕同时说话、弹窗按钮区、滚动末尾、焦点变化、世界空间边缘、实际支持的字号和屏幕比例。未检查的组合写清楚，不承诺“任何分辨率均无重叠”。
4. **字形验证：** 检查缺字、方框、回退字体行高、标点、换行和方向；使用游戏内实际渲染作为最终证据。

对防溢出与局部字号适配，验收须同时包含横向边界、总行高和相邻 UI：确认辅助语言完整可读、主语言字号未被误改、缩放作用域正确结束。保留修正前后同一场景的证据；只有文本行宽估算或静态截图不足以验证动态姓名、数值、滚动和多条字幕同时出现的全部情况。

分开报告：数据规则通过、最终包通过、游戏加载通过、哪些画面与交互通过。目视抽查不能代替数据完整性，数据完整性也不能代替目视抽查。

## 原文件保护与安装

- 原生模组目录、资源覆盖、加载器、运行时文本替换等没有统一优先级；按当前引擎能力选择侵入最小、可验证的方案。需要新加载器时限定职责、识别版本和冲突，不附带无关玩法改动。
- 建立基线清单，至少记录相关文件路径、大小、版本及可靠校验。声明“字节未变”需要对应哈希或字节证据；仅比较修改时间和大小时准确说明证据范围。
- 安装前校验发布源文件、目标版本和同名冲突；未知文件不覆盖。升级应能识别并处理自己的旧版本，而不是让用户提前覆盖用于卸载的旧清单。
- 游戏或资源编辑器占用文件时避免替换。若必须关闭并存在未保存进度，明确实际损失并按当前会话授权及工具要求处理；不要擅自强杀，也不要重复索取已经充分给出的常规授权。
- 卸载仅删除或还原补丁清单中、归属和校验相符的文件，拒绝删除被他人替换或修改的同名文件。安装中途失败应有恢复办法。
- 确实需要替换原文件时，保留对应版本原件与恢复说明；默认只备份会受影响的文件，不要求复制整个游戏。存档测试前按实际风险备份相关用户数据，绝不把存档、账号信息或私人日志带入发行包。

## 交付内容与覆盖统计

交付可复现构建所需的适配代码／配置、补丁及版本清单、安装卸载／回退方法和简明教程，保留实际依赖与许可证信息。工具与原游戏资源的再分发取决于许可，不把它们默认打包。

以原始唯一记录为基础，按内容类别列出总数、有效译文数、成功双语数、未翻译／回退原因及较上一版本的变化。类别应来自当前游戏实际盘点，而非照抄技能示例表；另列尚未评估的数据来源、没有稳定ID的内容及发现依据。共享记录与多个消费者分开统计；不能把一个ID在五处显示算成五条翻译，也不能把数据条目覆盖率说成所有剧情／界面／游玩时长的覆盖率。

复查应同时从资源分布和玩家流程发现遗漏：未引用或运行时构造的文本、条件解锁界面、不同玩法模式、说明展开／悬浮／焦点态，以及语言表之外的素材文字。按当前版本和授权范围做合理检查，不要求游玩所有分支才可交付，但须如实说明检查边界，并继续处理已经发现且可行的范围内遗漏。

最终说明应包括：主辅语言、支持的版本、实际新增内容、布局策略、未支持的格式或场景、哪些测试与画面已检查、启动设置、安装／升级／卸载入口。保留逐ID诊断记录在项目工作目录；公开包只含必要的脱敏信息。

## 技能或项目规则的回归场景

可用下列情境检查实现者的决策，而不是要求每个项目重复执行虚构测试：

| 情境 | 应检查的行为 |
| --- | --- |
| 一个ID同时用于操作指南和设置标题 | 识别共享引用；隔离或采用共同安全策略，不全表拼接 |
| 很多对白因原有硬换行而丢失译文 | 调查真实容量并恢复可容纳条目，不全量强塞，也不永久接受整类过滤 |
| 用户指定非中英组合、辅助语言在上或从右向左阅读 | 按指定组合和顺序试排，检查字形与双向混排，不强制套用主语言在上／在左的示例 |
| 示例表未列出的卡牌效果、体育判罚或场景标牌 | 纳入实际盘点，按消费者评估，不以不在表格中为由跳过 |
| 表格中列出的类别已完成，但仍有可处理的表外文字 | 继续覆盖并更新记录，不将示例清单完成当作全面处理完成 |
| 同一格式参数需要在双语中出现两次 | 核验格式化器、类型与实际值，不仅比较参数集合 |
| 两种语言的姓名、数量或动作参数位置不同 | 保持各自完整语义单元，不围绕共享参数交错拼句；核验最终运行时组合 |
| 一句含多个数值、对象或不同按键 | 关联清晰且编号不冒充数量，不把多个参数都替换成模糊的同一指代 |
| 参数位于样式属性，或原生颜色延伸到字符串末尾 | 区分控制属性与可见参数，按引擎语法隔离作用域，不把属性改成可见指代 |
| 用户只举一种物品说明和一个通知 | 从共同规则扩展检查其他消费者及反例，不建立只涵盖示例的修补白名单 |
| 说明起点接近列表行底部 | 先检查单行左右／横向滚动或详情区，增高时同步完整列表布局 |
| 长文区已有原生纵向滚动 | 验证范围和焦点，保留长文双语，不按字数直接放弃 |
| AutoFit后仍有超长主语言回退 | 检查回退路径也受合理换行与可读性限制 |
| 双语字幕变窄后行数增加，或教程说明挡住按钮 | 联合检查宽高、父级边界和相邻控件，不能只以单行变短判断修复完成 |
| 必须缩小辅助语言才能容纳全文 | 局部调整并确认可读下限、主语言字号与格式恢复；不无限缩小、不截句、不把未实测结果称为零越界 |
| 补丁读回通过但未启动游戏 | 只报告资源已验证，不声称已运行或所有场景无重叠 |
| 安装目标有不同哈希的同名文件 | 拒绝覆盖，先辨认归属和版本，不以“完成安装”为由删除 |
